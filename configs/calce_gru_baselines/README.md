# CALCE SOH-only GRU baseline suite

Four matched experiments are provided for `CALCE_CX2_37.pkl`:

1. `nometa_l500`: plain GRU encoder-decoder, target SOH only, L=500
2. `nometa_l100`: plain GRU encoder-decoder, target SOH only, L=100
3. `meta_l500`: target-aware weighted second-order MAML, SOH only, L=500
4. `meta_l100`: target-aware weighted second-order MAML, SOH only, L=100

All four runs use the same `GRUSeq2Seq`: scalar GRU encoder, scalar GRU decoder,
hidden size 64, one recurrent layer, and a linear SOH head. Teacher forcing is
zero in training and evaluation. Every future is therefore generated by feeding
the preceding prediction back into the decoder.

The two non-meta runs do not use fixed windows. After reserving the last 20
support cycles for recursive validation, they train on every variable
prefix-to-remaining-future pair. For a training prefix of length `T`, the pairs
are `1 -> 2..T`, `1..2 -> 3..T`, ..., `1..T-1 -> T`. L is the only configuration
difference inside the non-meta pair. Historical window runs and code remain
available for reproducibility, but this suite no longer calls them.

The meta pair also differs only in L. Both use same-family CX2 sources, MMD-QP
target weights, full second-order MAML, 2300 iterations, and fast/full target
adaptation. Source inner/query rollouts and target adaptation are fully recursive
with teacher forcing zero.

Run one experiment:

```bash
python scripts/run_calce_gru_baseline_suite.py \
  --experiment nometa_l500 \
  --target CALCE_CX2_37.pkl \
  --device cuda
```

Replace the experiment with `nometa_l100`, `meta_l500`, or `meta_l100`.

Run all four sequentially:

```bash
python scripts/run_calce_gru_baseline_suite.py \
  --experiment all \
  --target CALCE_CX2_37.pkl \
  --source-mode same_family \
  --device cuda
```

Individual results remain under `outputs/runs/`. The suite runner also writes a
small index containing all four paths under
`outputs/calce_gru_baseline_suites/<timestamp>/suite_manifest.json`.
The same directory contains `baseline_comparison.csv`,
`baseline_comparison.json`, and `baseline_comparison.png` with matched
trajectory and RUL metrics. These files are updated after each completed run,
so already-finished experiments remain easy to inspect if a later run stops.
